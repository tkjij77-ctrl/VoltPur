# 📊 القياس في VoltPur — المنهجية الصادقة

> **القاعدة الحاكمة:** لا يُنشر رقم بلا ملف قياس موجود في المستودع يمكن فتحه ومراجعته.
> هذه النسخة **حذفت** كل الأرقام التي نُشرت سابقًا بلا قياس وصفتها بصراحة في قسم «أرقام مسحوبة» أدناه.

---

## 1) ما نقيسه فعليًا (وهو متاح لك الآن)

الأداة الوحيدة المعتمدة للتشغيل المحلي:

```
/voltpur benchmark        (يحتاج صلاحية voltpur.admin.benchmark أو OP، مع كولداون 30 ثانية)
```

تُخرج السطور التالية وتضيفها إلى `logs/voltpur-benchmark.txt` (مع تدوير تلقائي عند 512 KiB):

| القياس | المصدر | ملاحظة الدقة |
|---|---|---|
| TPS ‎(1m/5m/15m) | `Bukkit.getServer().getTPS()` | متوسطات Paper الرسمية |
| MSPT | `Bukkit.getServer().getAverageTickTime()` | متوسط زمن التِك |
| الكيانات / الـ chunks لكل عالم | `World#getEntities`, `#getLoadedChunks` | يُقرأ للحظة القياس فقط |
| الذاكرة | `Runtime` + حصة الحاوية (cgroup) | يوضح الفرق بين المضيف والحاوية |
| الهوبرات | عدّاد: إجمالي / خاملة | **لا يُعدّل أي حالة** |
| حالة الموديولات | `VoltPurGuard` (runs/fails) | يكشف موديولًا فاشلًا بصمت |

**مثال على شكل المخرج (بنية فقط):**
```
== VoltPur benchmark [manual] @ 2026-09-17 15:04:11 ==
VoltPur   : 26.2.0-rc2 | MC 26.2
TPS       : 20.00 / 20.00 / 20.00 (1m, 5m, 15m)
MSPT avg  : 3.41 ms (Paper average tick time)
  world   : world (E=142, C=441)
Entities  : 142
Chunks    : 441
Heap      : 812 MB used / 4096 MB max (container RAM available: 4096 MB)
Hoppers   : 37 total / 21 idle (empty + no source above + unpowered)
ModuleGuard: runs=612 failures=0 (no module failures recorded)
```
> الأرقام أعلاه **توضيحية لبنية المخرج**، وليست قياسًا منشورًا. القياس الحقيقي هو ما يظهر عندك.

## 2) كيف تُقارن أي تحسين بطريقة صحيحة

1. **خط أساس (Baseline):** شغّل نفس السيرفر بنفس العالم واللاعبين، ونفّذ `/voltpur benchmark` **3 مرات** بفارق دقائق، واحفظ الملف.
2. **طبّق تغييرًا واحدًا فقط** (مثال: `/voltpur optimize` مع `auto-tune=true`) ثم أعد الريستارت.
3. **أعد القياس** بنفس الظروف (نفس عدد اللاعبين، نفس المدة).
4. اقبل النتيجة فقط إذا كان الفرق أكبر من **هامش الضوضاء** (عادة ±5% على MSPT في سيرفر هادئ) وظهر في **ثلاث قياسات متتالية**.
5. احفظ المقارنة في `docs/measurements/<التاريخ>-<التغيير>.md` (الدليل مطلوب حتى يصبح الرقم قابلًا للنشر).

**قوالب القياس:** يوضع كل ملف قياس في `docs/measurements/` بهذا الشكل:
```
# <التغيير> — <التاريخ>
البناء: build #<n> (<sha>)  |  Java: <version>  |  الأجهزة/الحصة: <RAM/cores>
قبل:  MSPT=… TPS=… (3 قياسات)
بعد:  MSPT=… TPS=… (3 قياسات)
الفرق: <x%>  |  القياس الخام: logs/voltpur-benchmark.txt (مُرفق)
```

## 3) أرقام مسحوبة (Withdrawn claims)

هذه الأرقام كانت منشورة سابقًا في هذا الملف بوصفها «أرقامًا حقيقية». **أُلغيت** لأنها لا تحقق شرط الدليل:

| الادعاء السابق | لماذا أُلغي |
|---|---|
| «Hopper أسرع 62% (8.2ms ← 3.1ms)» | **لا يوجد patch هوبَر في هذا الفورك** (مسجّل `PLANNED`)، ولا ملف قياس في المستودع، ولا أثر لأداة القياس المزعومة |
| «Item tick أسرع 50%، RAM أقل 18%» | لا ملف قياس؛ والأداة الحالية لا تقيس زمن تِك العناصر أصلًا |
| «Boot Time أسرع 1.6%» | الفرق أصغر من هامش الخطأ - لا يُنشر كنسبة |
| «Chunk load أسرع 4%» | نفس السبب |
| «Entity Activation وفّر 80%» | الميزة من Paper أصلًا (EAR)، وليست إضافة VoltPur |
| «Bedrock/تونل: 300% استقرار» | لا يوجد قياس ping/jitter مرفق |

**ملاحظة سيادية:** هذه الأرقام مُسحت أيضًا من `PTERODACTYL_FIX.md` (الذي كان يعرض مخرجات إقلاع وهمية مثل `Loading 21 modules`، وهي ميزة غير موجودة في الكود الحالي).

---

## 4) ما سيتغيّر في المستقبل القريب (المرحلة 2)

- تشغيل قياس تلقائي داخل CI: يقلع السيرفر headless، ينفّذ `/voltpur benchmark`، ويُنتج ملفًا حقيقيًا `docs/measurements/ci-<build>.md`.
- نظام `Claim → Probe`: كل ادعاء في التوثيق يُربط بأمر قياس؛ والبناء يفشل إذا كان ادعاء بلا قياس.
- عندها فقط، وبهذا الترتيب، تصبح «الأرقام الحقيقية» جملة ممكنة في README.
